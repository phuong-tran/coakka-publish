# CoAkka Runtime 1.4.1 Corrective Release

Runtime `1.4.1` replaces the incomplete native platform coverage of
`1.4.0+2cee86bf`. The release is built from full core source commit
`9e02a51d7f0e4a231e2f71fe6d19ce02724277c9`.

## Corrected Boundary

The native package, `coakka-client`, and `coakka-runtime-inspect` each contain
exactly these five platforms:

- Linux ARM64
- Linux x86-64
- macOS ARM64
- Windows ARM64
- Windows x86-64

The native package is
`runtime/native/releases/1.4.1+9e02a51d/coakka-runtime-native-v2-1.4.1.tar.gz`
with SHA-256
`ef31cd8bc709bd71d62dab0497f2513990f9023bda5e128631842ece5360394f`.
Its manifest and checksum file are authoritative for the platform entries.

- JVM, Spring Boot, and Quarkus: `1.4.1-g9e02a51d-4e7cda4`
- Source connector artifacts: `1.4.1+9e02a51d-4e7cda4`

The Python, NuGet, and npm packages are registry-verified. The NuGet.org
download contains the exact staged entries plus its repository signature. npm
serves the exact Node.js, Bun, and Electron `1.4.6` versions under the
`latest` dist-tag.

## Verification Gates

- All five native libraries pass binary-format, architecture, dependency, and
  exact-export checks.
- Linux ARM64/x86-64 and macOS ARM64 execute on matching hosts.
- Windows ARM64 executes on Windows 11 ARM64: runtime lifecycle, JVM
  ask/deadletter, `coakka-client` version/doctor, and
  `coakka-runtime-inspect` command smokes pass.
- `coakka-client` and `coakka-runtime-inspect` archives pass per-platform
  format, checksum, and dependency verification.
- Linux `coakka-runtime-inspect serve` HTTP smokes pass on both architectures.
- `coakka-runtime-inspect` keeps its event-loop implementation as a private
  static tool dependency. The Windows resolver rejects its import archive, and
  release dependency gates reject dynamic event-loop or protobuf dependencies.
- The publish manifest, native linkage, public-surface scanner, and JVM native
  bundle gates pass before registry publication.

## Publication Rule

No `current` pointer or package-manager status is advanced from candidate to
current until the registry returns the exact published version and digest.
