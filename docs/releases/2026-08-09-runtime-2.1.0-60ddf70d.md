## File Lane

Runtime 2.1.0 adds the independent file lane: a bounded point-to-point path
for transferring one immutable file from Service A to Service B after Service
B authorizes and prepares the exact transfer identity.

The application control plane carries the transfer ID, a cryptographically
strong single-use token, expected byte count, SHA-256 digest, receiver host,
and receiver port. File bytes do not travel inside a runtime `Envelope`.
Service B writes a staging file, checkpoints durable progress, verifies the
complete digest, and publishes the destination only after verification.

Direct mode uses the operating-system file-transfer facility available on the
host: Linux/macOS `sendfile` and Windows `TransmitFile`. This describes the
file-to-socket portion of the send path. The complete transfer is not an
end-to-end zero-copy claim: the receiver still writes storage, verifies the
file, and performs an atomic publish boundary. TLS and mTLS intentionally use
the encrypted streaming path because encryption changes the ownership and
copy boundary.

Use the file lane for large media, models, datasets, backup/checkpoint files,
build artifacts, or diagnostic bundles exchanged between trusted application
services. Use normal messages for commands and events. Use object storage,
CDNs, or HTTPS when content needs broad distribution, caching, browser access,
or long-lived addressing.

The full workflow, JVM/JNA/JNI bridge explanation, Service A and Service B
examples, authorization rules, lifecycle, cancellation, resume behavior, and
result vocabulary are documented in
[Runtime File Transfer](../runtime-file-transfer.md).

## Message And Failure Semantics

The common message documentation now defines the complete public `Envelope`,
including `ONE_WAY`: it suppresses reply production but does not suppress
admission, routing, transport, observability, or deadletter behavior.

The deadletter map separates pre-admission rejection from failure after runtime
owns an envelope. It also defines TLS/mTLS behavior:

- invalid local TLS configuration is returned synchronously and does not
  create a deadletter;
- an outbound security failure for an admitted envelope creates
  `REMOTE_TRANSPORT_SECURITY_FAILED` with `transport-failure/1` metadata;
- an inbound handshake failure before a frame is decoded has no envelope
  identity and is recorded as a typed runtime event.

See [Envelope And Deadletter Map](../envelope-deadletter-map.md) and
[Runtime TLS And mTLS](../tls-and-mtls.md).

## Connector Surface

The file lane is available through the native C ABI and the JVM, Python,
Node.js, Bun, Electron main process, Go, C#, Rust, Swift, Zig, Mojo, and trusted
Tauri host lanes. Electron renderers and Tauri WebViews receive narrow
application intents rather than raw paths, tokens, or native handles.

Spring Boot and Quarkus consume the same documented JVM connector generation.
The JVM surface is the `JVM/JNA/JNI` native-bridge category; the current
implementation calls the C ABI through JNA.

| Linux x86-64 | `libcoakka_runtime_v2.so` | Host-native UTM build and file-lane roundtrip |
| macOS ARM64 | `libcoakka_runtime_v2.dylib` | Host-native build and file-lane roundtrip |
| Windows ARM64 | `libcoakka_runtime_v2.dll` | MSVC build; file-lane and 10 TLS/mTLS tests executed on Windows 11 ARM64 |
| Windows x86-64 | `libcoakka_runtime_v2.dll` | MSVC build; file-lane and 10 TLS/mTLS tests executed under Windows 11 ARM64 x64 emulation |

Every native library exports the same 115-symbol C ABI and reports the full
source commit through runtime introspection. Release verification also checks
binary architecture, dependency policy, manifest identity, archive hashes,
and extraction on matching hosts.

The Windows runtime gate now executes the file-lane roundtrip as part of the
release build. That gate caught and fixed a real CRT file-position issue after
source SHA-256 verification; the final 9,437,915-byte Windows transfer reaches
`COMPLETED + OK` independently on both sender and receiver.

## Publication Boundary

The artifact mirror, Maven repository, Go module, SwiftPM package, package
archives, native tools, and package-manager registries are separate release
channels. npm Node.js, Bun, and Electron `2.1.1` are published and
clean-install verified. PyPI and NuGet retain their 1.4.x registry coordinates
until their independent 2.1.0 publication and verification complete.

The public source tags are `coakka-runtime-go@v1.5.0` and
`coakka-runtime-swift@v2.1.0`. Go remains on semantic major `v1` because its
established module path does not carry the `/v2` suffix; both tags bundle
native generation `2.1.0+60ddf70d`.
